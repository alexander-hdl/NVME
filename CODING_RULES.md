# CODING_RULES — регистратор (STAND/RECORDER_SPEC.md)

Обязательны для всех пакетов работ (WP). Спецификация — `STAND/RECORDER_SPEC.md` (далее «спец»); при противоречии побеждает спец, а противоречие записывается в `INTEGRATION_NOTES.md`.

## 1. Язык
* SystemVerilog-2012, синтезируемое подмножество Vivado 2025.2: `always_ff`, `always_comb`, `logic`, `typedef struct packed`, `enum`, `function automatic`, `generate`.
* Запрещено в RTL: защёлки, `initial` (кроме ПЗУ и начального значения toggle-регистров в `cdc_pulse`/`cdc_bus`), `#задержки`, `fork`, классы, `$random`, многократное присваивание сигнала из разных `always`, `inout` (кроме топа), деление и умножение на переменную в `link_clk`.
* Один модуль на файл; имя файла = имя модуля. Шапка: назначение, домен(ы), протокол портов, ссылка на раздел спеца. Комментарии в коде — по-английски.
* Типы, коды, константы — только из `rec_pkg` / `nvme_host_pkg`. `rec_pkg` не импортирует `nvme_host_pkg`.

## 2. Имена
* Модули и сигналы — `snake_case`; параметры и константы — `UPPER_CASE`; регистры — суффикс `_q`; активный 0 — `_n`.
* Порты — как в разделе 4.4 спеца, буква в букву (ширина, направление, имя).
* Экземпляры — `u_<модуль>[_<роль>]`; экземпляры `cdc_bus` — с префиксом `u_cdc_bus` (на это опирается XDC).

## 3. Домены и CDC
* У каждого порта в комментарии — домен (`// link`, `// ui`, `// user`).
* Любое пересечение — только через `rtl/common/cdc_pulse`, `cdc_bus`, `cdc_sync`, `axis_fifo_async`, `tdp_ram_2clk`. Читать сигнал чужого домена напрямую запрещено.
* Внутри примитивов имена обязательны: первый FF синхронизатора `*_cdc_s0_q` с `(* ASYNC_REG = "TRUE" *)`; регистр данных источника `cdc_bus` — `hold_q`, приёмника — `dst_data_q` (без `ASYNC_REG`).
* Контракт сброса — спец 4.3: toggle источника не сбрасывается; приёмник при сбросе копирует синхронизированный toggle без импульса; `cdc_bus` без ack, `HOLD_CYC ≥ ⌈6·f_src/f_dst⌉+2`.
* Многобитный сигнал через `cdc_sync` — только квазистатика или липкий флаг (и это написано в комментарии).

## 4. Сбросы
* Синхронный, активный 1, свой на домен (`rst` в порту модуля). Асинхронный — только в синхронизаторах сброса в топе.
* Сброс регистратора (`rec_rst`) и ядра (`core_rst_n`) раздельны (спец 4.2). `ui_clear` — функциональная очистка импульсом, не сброс.
* Сбрасывать управление и счётчики; широкие тракты данных — не обязательно.

## 5. Интерфейсы и тайминг
* AXIS: `valid` не зависит от `ready`; данные стоят до приёма. Импульсы — ровно 1 такт. Выходы модуля — регистры.
* `user_clk` (125 МГц): не более одного сумматора/сравнения 32 бит между регистрами. `link_clk` (200 МГц): операции > 32 бит — с регистром на выходе. BRAM — через `sdp_ram` / `tdp_ram_2clk` / FIFO из `rtl/common`.

## 6. Тесты
* `sim/tb/tb_<name>.sv` (модуль `tb_<name>`) + `sim/tb/tb_<name>.f` (пути от корня, пакеты первыми). Запуск: `sim/scripts/run_xsim.sh <name>`; без аргумента — вся регрессия.
* Самопроверка (scoreboard, эталон), не просмотр волн. Ошибка → `$fatal`; успех → `$display("TEST PASSED")`. `SIM_FAST` для мс-таймеров; ≤ 2 мин на тест.
* **Отрицательная проверка обязательна**: каждый тест хотя бы раз вносит ошибку (порча данных, неверный ввод, сброс посреди операции) и проверяет, что она обнаружена с точным кодом / адресом. Тест без такой проверки не принимается.
* `xvlog -sv` без предупреждений в своих файлах; перед сдачей — вся регрессия зелёная (22 старых теста + новые).

## 7. Владение и изменения
* Правите только файлы своего WP (спец 10.1). Нужна правка чужого файла или интерфейса — запись в `INTEGRATION_NOTES.md` и запрос оркестратору; код меняется после правки спеца.
* Git: своя ветка `wp<N>-<name>`, мелкие коммиты, сообщения по-английски; `fpga/build/` не коммитить.
