# NVMe-хост на ALINX AX7A200B (AC7A200) + адаптер PCIe→M.2 — архитектура стенда и методика испытаний

Статус: v0.3 (2026-11-18): PERST# через L16 (провод не нужен); пробная сборка выполнена, тайминг сошёлся (§9). Базовый контракт RTL — `ARCHITECTURE.md` (v1.1, KC705).
Этот документ описывает **перенос** на Artix-7 и стенд из платы ALINX и адаптера `STAND/PCB/PCIe-m2`.

---

## 1. Вывод о совместимости

**Связку использовать можно, DDR не нужна.** Ограничения:

| # | Ограничение | Следствие |
|---|---|---|
| C1 | На несущей плате AX7A200B (и старой AX7A200) к краевому разъёму PCIe разведены только **2 линии** GTP (ch2, ch3). Разъём механически x4, в руководстве раздел назван «PCIe x4», но в таблице выводов только x2. Ch0/ch1 идут на SFP. | Канал **Gen2 x2**: потолок ≈1 ГБ/с на линии, ≈0.85 ГБ/с полезных данных (на KC705 было x4, ≈1.7 ГБ/с). Для запуска NVMe этого достаточно. |
| C2 | PERST# краевого разъёма (A11) заведён на FPGA, вывод **L16** (таблица PCIe x2 в китайской версии руководства; в английской его нет). В примерах ALINX это вход (режим endpoint). | Root Port сам выдаёт PERST# на L16 → A11 → слот адаптера → XP1 → M.2. **Провод не нужен** (см. §3.3). |
| C3 | В Artix-7 логика медленнее, чем в Kintex-7: на KC705 запас по `user_clk` 125 МГц был всего +0.345 нс. | Основной риск — тайминг. Нужна пробная сборка; меры перечислены в §4.4. |
| C4 | BRAM: в XC7A200T 365 RAMB36 (в XC7K325T их 445). | Кольцо 8×128 КиБ (256 RAMB36) помещается, но по умолчанию берём 4×128 КиБ (128 RAMB36): для x2 этого хватает, а трассировка проще. |

Само ядро `pcie_7x` v3.3 в режиме Root Port на Artix-7 поддерживается: Gen2, до x4, интерфейс 128 бит / 125 МГц на кристалле -2.
На плате стоит XC7A200T-**2**FBG484I.

## 2. Что на адаптере `PCIe_M2_Adapter` (по `Schematics.PDF`)

| Узел | Компонент | Назначение / замечание |
|---|---|---|
| XP2 | Molex 87715-9306, **гнездо** PCIe x16 | Сюда вставляется плата FPGA (AX7A200B), разведены линии 0..3. |
| XP3 | TE 1-2199230-6, M.2 M-key | Сюда ставится NVMe SSD (PCIe x4). |
| DD2 | Si52142 + кварц 25 МГц (Z2) | Два выхода 100 МГц HCSL: `CLK_HOST` на A13/A14 слота, `CLK_M2` на M.2. Выходит **общий опорный такт** у FPGA и SSD (common clock), как на KC705. SS0/SS1 задаются джамперами XP4/XP5. |
| C7/C8, C9/C10 | 0.1 мкФ последовательно в REFCLK | Тактовые линии развязаны по постоянному току (см. риск R4). |
| U1 | PTH08T230W, 12 В → 3.3 В | Питание M.2 (до 6 А). |
| DD1 + SA1 | TPS3808 + кнопка | `SYS_RESET#`: супервизор питания и ручной сброс. |
| XP1 (PLD-4) | джампер | Выбор источника `PERST_M2#`: `PERST_HOST#` (A11 слота) или `SYS_RESET#`. |
| XP7, XP9 | джамперы | Подача +3.3 В / +12 В на контакты питания слота (`+3.3V_FPGA`, `+12V_FPGA`). |
| XP8, XP11 | джамперы | WAKE#, PRSNT#. Для стенда не используются. |
| DD3 | SN74LVC1GU04 | CLKREQ# от M.2 → инвертор → OE генератора. |
| Z1 | KXO-V32T | SUSCLK 32 кГц для M.2. |

**Проверка разводки линий** (имена в CEM и M.2 даны со стороны хоста):

| Слот (вывод карты) | Цепь адаптера | M.2 | Итог |
|---|---|---|---|
| A16/A17 (PERp0/n0, передатчик карты) | PCIe_TX0 | 49/47 (PETp0/n0, приёмник SSD) | ✔ TX карты → RX SSD |
| B14/B15 (PETp0/n0, приёмник карты) | PCIe_RX0 | 43/41 (PERp0/n0, передатчик SSD) | ✔ |
| A21/A22, B19/B20 | TX1 / RX1 | 37/35, 31/29 | ✔ |
| A25/A26, B23/B24 / A29/A30, B27/B28 | TX2,3 / RX2,3 | 25/23, 19/17 / 13/11, 7/5 | ✔ (у AX7A200B не используются) |

Порядок линий прямой, переворота нет. Разделительных конденсаторов в линиях на адаптере нет, и они не нужны:
TX-конденсаторы стоят на AX7A200B (по руководству ALINX) и на самом SSD.

## 3. Что на AX7A200B / AC7A200 (руководство ALINX AX7A200B, Rev 1.0)

### 3.1 Выводы FPGA, нужные проекту

| Сигнал | Вывод FPGA | Стандарт | Примечание |
|---|---|---|---|
| PCIe lane0 TX P/N | D7 / C7 | GTP | MGTPTX3_216 → IP lane 0 |
| PCIe lane0 RX P/N | D9 / C9 | GTP | MGTPRX3_216 |
| PCIe lane1 TX P/N | B6 / A6 | GTP | MGTPTX2_216 → IP lane 1 |
| PCIe lane1 RX P/N | B10 / A10 | GTP | MGTPRX2_216 |
| (SFP1) TX/RX | B4,A4 / B8,A8 | GTP | ch0, при варианте A — IP lane 3 (см. §4.2) |
| (SFP2) TX/RX | D5,C5 / D11,C11 | GTP | ch1, при варианте A — IP lane 2 |
| PCIe REFCLK 100 МГц | F10 / E10 | MGTREFCLK1_216 | из слота, т.е. от Si52142 адаптера, развязан конденсаторами |
| GTP REFCLK 125 МГц | F6 / E6 | MGTREFCLK0_216 | генератор ядра; для PCIe **не используется** |
| SYS_CLK 200 МГц | R4 / T4 | DIFF_SSTL15 (банк 34, 1.5 В) | → `free_clk`, `LINK_CLK_HZ = 200_000_000` (как на KC705) |
| RESET (кнопка) | F15 | LVCMOS33, нажата = 0 | → `board_rst_n` |
| KEY1..KEY4 | L19, L20, K17, J17 | LVCMOS33, нажата = 0 | START / STOP / страница LED / резерв |
| LED1..LED4 | L13, M13, K14, K13 | LVCMOS33, **горит при 0** | статус |
| UART TX / RX (USB-UART) | L15 / L14 | LVCMOS33 | `UART1_TXD` / `UART1_RXD`: телеметрия (новое) |
| PERST# → M.2 | **L16** (`PCIE_PERST`, ламель A11 через R102) | LVCMOS33, банк 15 | IO_L23P_T3_FOE_B_15; FOE_B действует только при загрузке BPI, плата грузится из SPI |

Выводы из руководства нужно сверить со схемой несущей платы и с примером XDMA от ALINX: это обязательный пункт до первой прошивки.
Номера GT-сайтов `GTPE2_CHANNEL_X0Y?` для банка 216 берём из Vivado (Device view) или из XDC примера ALINX.

### 3.2 Питание (рекомендуемая схема)

* Внешний блок 12 В подключается **к адаптеру** (XS1 / XP10 / XP12), выключатель SB1.
* XP9: `+12V → +12V_FPGA` замкнуть. AX7A200B получает питание через золотые контакты (руководство ALINX это допускает).
* XP7 (`+3.3V_FPGA`) **разомкнуть**: несущая плата делает 3.3 В сама.
* Свой разъём питания AX7A200B **не подключать одновременно** со слотом. Как на плате объединены источники, в руководстве не сказано.
* Бюджет мощности: SSD до 2.5 А × 3.3 В (≈8 Вт) плюс плата FPGA ≈5–8 Вт. Блок 12 В / 3 А с запасом.

### 3.3 PERST#

* Путь сигнала: FPGA L16 → R102 → ламель A11 → слот адаптера (`PERST_HOST#`) → джампер **XP1 в положении `PERST_M2# ↔ PERST_HOST#`** → M.2 PERST# (вывод 50). Провод не нужен.
* Уровень 3.3 В LVCMOS совпадает с M.2. Подтяжку к 3.3 В даёт R1 10 кОм на адаптере.
* Пока FPGA не сконфигурирована, вывод L16 в высоком импедансе, и PERST# поднимает подтяжка. SSD может начать
  обучение раньше времени, но после конфигурации `link_bringup` сразу держит PERST# низким ≥ 100 мс (D12) и
  запускает SSD заново. Проверка — тест T1.4.
* Проверить перед первым включением (плата обесточена): L16 прозвонить нельзя (BGA), поэтому прозвонить A11 ↔ R102
  и убедиться, что на пути нет микросхемы-буфера. Если буфер найдётся, запасной вариант — провод J11-3 (G21) → XP1 `PERST_M2#`
  и `PACKAGE_PIN G21` в `ax7a200b_board.xdc`.
* Альтернатива для первых опытов: XP1 в положение `SYS_RESET#` и сброс SSD кнопкой SA1. Это допустимо только для первых опытов: FPGA тогда не управляет последовательностью PERST# (D12 в `ARCHITECTURE.md`), и автоповтор `link_bringup` не работает.

## 4. Архитектура FPGA-проекта

### 4.1 Структура

```
                         AX7A200B (XC7A200T-2FBG484I)                         адаптер PCIe→M.2
 SYS_CLK 200M R4/T4 ─IBUFDS─BUFG─ free_clk ─┐
 RESET  F15 ───────────────────────────────┤
 KEY1..4 ── debounce ── START/STOP/PAGE ───┤
                                           ▼
 ┌─────────────────────── ax7a200b_top (НОВЫЙ) ──────────────────────────┐
 │  pattern_gen (из kc705_top) ─128b@user_clk─┐                           │
 │  status_uart (НОВЫЙ) ◄── stat_*, status_* ─┤                           │  UART L15 → USB-UART → ПК
 │  led_pages (4 LED)  ◄──────────────────────┤                           │
 │                                ┌───────────▼──────────────┐            │
 │                                │ nvme_host_top (БЕЗ ИЗМ.) │── PERST# ──┼─ L16 → A11 → XP1 → M.2 PERST#
 │                                │  link_bringup / enum /   │            │
 │                                │  nvme core / data_ring   │            │
 │                                │  pcie7x_wrapper          │            │
 │                                │   └ pcie_7x_0 (Artix IP) │◄═ x4 GTP ═╪═ lane0,1 → слот → M.2
 │                                └──────────────────────────┘            │   lane2,3 → SFP (пусто)
 └────────────────────────────────────────────────────────────────────────┘
 PCIe REFCLK F10/E10 ◄── слот A13/A14 ◄── Si52142 ──► M.2 REFCLK  (общий такт)
```

Ядро NVMe, адаптеры TLP, `link_bringup`, перечисление и кольцо данных переносятся **без изменений**: память хоста целиком в BRAM (D4–D7), DDR не трогаем.
Меняется только «обвязка платы».

### 4.2 Конфигурация ядра PCIe: вариант A (основной) и вариант B (запасной)

**Вариант A: IP настроено как x4 Gen2, 128 бит @ 125 МГц, канал сам сужается до x2.**
* Порты `pci_exp_*[3:0]` остаются как есть. Lanes 0/1 ставятся на GTP ch3/ch2 (слот), lanes 2/3 на ch1/ch0 (разъёмы SFP).
* Модули SFP **вынуть**. Тогда на линиях 2/3 нет нагрузки, Receiver Detect их не находит, и LTSSM обучает канал x2. `status_link_width` покажет 2'b01 (x2).
* Плюсы: ни одной правки в RTL, то же `.xci`, сменились только деталь и LOC. Минусы: заняты все 4 GTP (SFP на этой плате всё равно не нужны).
* Проверить: ядро Artix-7 x4 допускает произвольные LOC линий в пределах квада 216 (на Kintex перенос в квад 118 прошёл).

**Вариант B: IP x2 Gen2, 64 бит @ 125 МГц.** Нужен только если вариант A не обучается (например, ядро требует ответа от всех линий или сайты GT недопустимы).
* Нужны новые `pcie7x_rx_adapt64` / `pcie7x_tx_adapt64` с преобразованием 64↔128 перед внутренней шиной `tlp_axis`. Ядро NVMe остаётся 128-битным.
* Объём работы около 2 модулей + тесты. Пропускная способность та же: 64×125 = 8 Гбит/с, это и есть Gen2 x2 после 8b/10b.

### 4.4 Тайминг на Artix-7: план мер (по возрастанию цены)

1. Пробная сборка «как есть» (вариант A, 4 слота). Цель — `userclk2` WNS ≥ 0.
2. Если не сходится: выходной регистр BRAM (`DOA_REG=1`) в `data_ring` / `hostmem_rams` с компенсацией задержки в читающих автоматах. Это первые кандидаты (отмечено ещё в README fpga/).
3. Регистровые срезы (`axis_skid`) на границах `tlp_tx_arb` → `pcie7x_tx_adapt` и `pcie7x_rx_adapt` → `tlp_rx_demux`.
4. Стратегии `Performance_ExplorePostRoutePhysOpt`, Pblock кольца рядом с блоком PCIe.
5. Крайний случай: вариант B на 64 бит @ 125 МГц. Он даёт ту же пропускную способность x2, но разрядность путей вдвое меньше.

### 4.6 Управление и индикация

| Орган | Функция |

| KEY1 | START |

## 5. Методика испытаний

Принцип: каждый уровень проверяет один новый слой и имеет **численный критерий прохождения**. Вперёд идём, только если пройден предыдущий уровень.
Инструменты: Vivado Hardware Manager + ILA, терминал UART, осциллограф ≥ 500 МГц (для REFCLK), ПК с Linux и слотом M.2 или USB-NVMe боксом для чтения SSD.

### Уровень 0. Моделирование (до железа)

| Тест | Что проверяем | Критерий |
|---|---|---|
| T0.1 | вся существующая регрессия (17 модульных тестов + `tb_top`) | без изменений проходит |
| T0.2 | `tb_top` с моделью SSD, обученной на **x2** (`link_width=2'b01`), и меньшим темпом CplD | запись 64 МиБ, шаблон совпадает, `status_link_width==01` |
| T0.3 | `tb_ax7a200b_top`: кнопки с активным 0, LED, PERST# ≥ 100 мс | временные соотношения по D12 |
| T0.4 | `status_uart`: приём кадра UART-моделью в тестбенче | строка совпадает с эталоном, 115200 ± 2 % |

### Уровень 1. Стенд без SSD

| Тест | Действие | Критерий |
|---|---|---|
| T1.1 | Питание от 12 В через адаптер, без SSD | 3.3 В на M.2 3.30 ± 0.1 В; PWR на AX7A200B горит; ток холостого хода записать |
| T1.2 | REFCLK осциллографом на TP1 (25 МГц) и на выводах M.2 53/55 и слота A13/A14 | 100 МГц ± 300 ppm; SSC выключен (XP4/XP5 по даташиту Si52142); размах дифф. ≥ 300 мВ на M.2 |
| T1.3 | Прошивка по JTAG, UART | кадр телеметрии каждую 1 с; LED heartbeat |
| T1.4 | PERST# осциллографом на M.2 вывод 50 | низкий ≥ 100 мс после включения, затем высокий; при повторах `link_bringup` видны новые импульсы |

### Уровень 2. Физический канал (с SSD)

| Тест | Действие | Критерий |
|---|---|---|
| T2.1 | ILA на `pl_ltssm_state`, `user_lnk_up`, `pl_sel_lnk_rate`, `pl_sel_lnk_width` | L0 за < 100 мс после PERST#; **Gen2, x2** |
| T2.2 | 10 циклов RESET | 10/10 L0; `link_retries == 0` |
| T2.3 | Без SSD | `link_fail` через заданный тайм-аут, LED ошибки, без зависаний |

### Уровень 3. Перечисление и регистры NVMe

| Тест | Критерий |
|---|---|
| T3.1 | В UART VID/DID/Class = 01_08_02 (NVMe), BAR0 назначен `0xC000_0000` |
| T3.2 | CAP/VS прочитаны, VS ≥ 1.2; CSTS.RDY = 1 после CC.EN; `status_nvme_ready` |
| T3.3 | Identify Controller / Namespace: MDTS, размер LBA и ёмкость в UART совпадают с `nvme id-ctrl` на ПК |

### Уровень 4. Корректность записи

| Тест | Действие | Критерий |
|---|---|---|
| T4.1 | Запись 1 ГиБ шаблоном, SSD — в ПК | `dd` + `fpga/tools/check_pattern.py --expect 1G`: 0 расхождений |
| T4.2 | 8 ГиБ и запись до конца пространства имён | 0 расхождений; `lba_range_err` взводится ровно на конце |
| T4.3 | STOP в середине, затем штатное выключение (CC.SHN) | SHST = 10b; у SSD после переноса в ПК не растёт `unsafe_shutdowns` (`nvme smart-log`) |
| T4.4 | Пониженные скорости генератора (1/2, 1/4, 1/8) | 0 расхождений; нет переполнения входного FIFO |

### Уровень 5. Производительность

| Тест | Критерий |
|---|---|
| T5.1 | Средняя скорость = `stat_bytes_done` / время (UART даёт отметки времени) | **≥ 750 МБ/с** на x2 Gen2 (≥ 88 % от ≈ 0.85 ГБ/с), пока не кончился SLC-кэш SSD |
| T5.2 | `stat_max_latency` и гистограмма (этап 2) | Задокументировать; для TLC-SSD после кэша скорость падает. Это свойство SSD, а не хоста |
| T5.3 | ILA на `rx_np_ok` / очереди запросов `hostmem_completer` | Нет остановок по кредитам NP дольше 1 мкс |

### Уровень 6. Устойчивость и совместимость

| Тест | Критерий |
|---|---|
| T6.1 | 100 прогонов по 1 ГиБ подряд (скрипт по UART, этап 2) | 100/100 без ошибок |

## 9. Результат пробной сборки (2026-11-12, Vivado 2025.2)

* Вариант A собран: IP x4 Gen2 128 бит для `xc7a200tfbg484-2`, LOC линий совпали с размещением IP по умолчанию
  (`GTPE2_CHANNEL_X0Y7..X0Y4`). Битстрим `fpga/build/ax7a200b_top.bit` готов. На плате **не проверен**.
* Ресурсы: 6 583 LUT (4.9 %), 6 585 FF, 142 RAMB36 (38.9 %, кольцо 4 × 128 КиБ), 4 GTP, 13 IOB.
* Тайминг: все ограничения выполнены, `userclk2` WNS **+0.098 нс**. Запас мал: проверять после каждой правки RTL.
* Чтобы тайминг сошёлся (§4.4, п. 2–3), в RTL добавлено:
  - выходной регистровый срез в `pcie7x_rx_adapt`;
  - регистры R (сырой заголовок) и P (декодированный запрос) перед рабочим запросом в `hostmem_completer`.

  Задержка «MRd → первый CplD» выросла на 3 такта (24 нс). На пропускную способность это не влияет. Регрессия из 20 тестов проходит.
* Попутно найдена и исправлена ошибка в `sim/scripts/run_xsim.ps1`: упавший тест засчитывался как пройденный.
