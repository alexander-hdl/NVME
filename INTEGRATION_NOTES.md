**Open issues (WP8).**
* D24 (new, WP5): `nvme_write_engine` / `data_ring` slot pointers go out of step after a READ of n commands (n mod N_SLOTS != 0); worked around by READ -> CORE_RST in rec_ctrl (costs a link re-train after every READ on the stand). * D3: the dead-`user_clk` watchdog is covered only by `tb_rec_ctrl` (the model clock cannot be stopped); the link-loss path is covered at system level (NEG_LINK).
* `$T stp` is the profile output (0 when idle; spec 2.5 "current NCO step"), `lk[3:2]` = `pl_sel_lnk_width` code (D16 open in WP9), `bpm` semantics (D13), ERR 0C only in unit tests.

**Test conditions worth knowing.** (a) The unthrottled `pcie7x_core_model` delivers read data at x4 Gen2 speed (up to 2 GB/s bursts, 1.25 beats per `ui_clk`); `vrf_tap`'s 512-entry FIFO overflows (`ovf=1`, results invalid) at that rate. The stand's link is Gen2 x2 (< 1 GB/s), so the tests set `u_core.rx_midpkt_gap_pct = 50`. A x4 link or a faster SSD would need either a deeper FIFO or a smaller read queue (open issue). (b) The default `TEL` is 1000 "ms" = 1 ms with SIM_FAST, i.e. the 3.9 ms `$T` lines saturate the wire; the tests send `TEL 0000` first (S1 measures the lines on purpose). (c) `pcie7x_wrapper_sim` shows the SSD only the first PERST# release (stand with `PERST_DRIVE=0`); the model supports no second one. (d) Idle `$T` has `stp=00000000` (rec_profile.step; the configured step is in `CFG?`), `lk=B` in the model (width code 10 = x4).

## WP1 (uart_rx, uart_tx, rec_cmd_parser, rec_tx_fmt): decisions, wire format, spec ambiguities

Tests (all PASS, xsim 2025.2, real 921600-baud timing): `tb_uart`, `tb_cmd_parser`, `tb_rec_tx_fmt`, bonus `tb_cmd_vectors` (151 strings generated from `tools/recorder.py` by `sim/vectors/gen_cmd_vectors.py` -> `sim/vectors/rec_cmd_vectors.txt`; LF/CR/CRLF and as one stream). `sim/vectors/check_fmt_lines.py` feeds every line written by `tb_rec_tx_fmt` (`sim/work/rec_tx_fmt/lines_dump.txt`) through `recorder.parse_line(strict=True)`: 95 lines, 0 rejected. Extra WP1 files beyond the table of 10.1: the two scripts above and `rec_cmd_vectors.txt`. OOC synth (xc7a200t-2, 200 MHz): uart_rx 28 LUT/34 FF, uart_tx 23/23, rec_cmd_parser 621/575 (WNS +0.74 ns), rec_tx_fmt 1713 LUT/3769 FF/1 RAMB18 (WNS +0.43 ns); almost all FF of the formatter are the 2884-bit `snap` copy required by 4.4 (spec 8.1 budgets 1500 FF for UART+parser+formatter+rec_ctrl together; if that matters, rec_ctrl must hold `snap` stable while `msg_ready=0` and the copy can be dropped).

Decisions (choose-one-definition items from WP9's list):
1. **`$T` length = 355 characters** (field list of 2.5 with names; 3.9 ms at 921600). The field list is binding, the "≈ 290" of 2.5 is not met. Order/widths exactly as `T_SPEC` of recorder.py. `v=` is `REC_VER` (01) (recorder.py rejects anything else).
2. **Widths of `!RR`**: `sid=h8 wr=h12 drp=h8 pad=h8 trc=h8 ddrm=h8 ssd=h16 cmd=h8 cer=h8 lat=h8 dur=h16` (what `FakeDevice` already prints). `!RV` as in 2.6 (first field `vb=h12`; `exp`/`got` are the `exp_dw`/`got_dw` of `vrf_res_t`, `end` = `snap.end_found`, `dur` = `snap.dur`). `!RP` as in 7.2 / recorder.py. `!RF ms=h8 ok=h1`, `!RM byt=h8 err=h8 adr=h8 dur=h16`, `!RD wr=h12 drp=h8 he=h8 dur=h16`. Values narrower than the field are zero extended (`pad`/`trc` 16 bit -> h8, `rtd` 16 bit -> h8), wider values are cut to the low digits.
3. **Reply forms**: `OK READ` for READ LAST / READ n / READ END (no fields), **`OK READ rsid=h8` for READ SID**, `OK FORMAT`, `OK MON`, `OK DTEST`, **`OK MEMTEST mib=h4`**, `OK STOP|PFAIL|ABORT`, bare `OK` after the `$T`/`!R*`/`P` lines (STAT?, RES?; opcode unknown to the formatter -> bare `OK`). `OK PROF` has the five forms of recorder.py. `OK SMART` the two forms; in the 17-field form `st` = `msg_arg0[15:0]` (log_status, WP2 does this), `ok`/`er` = `snap.smo`/`snap.sme`, `rtd` = `snap.rtd`.
4. **Terminators**: device -> PC lines end with **LF** only. PC -> device accepts CR, LF, CRLF and LFCR; blank / blank-with-spaces lines are ignored, so CRLF is one line (answers WP9 item 11; `--eol` may be anything).
5. **Parser error mapping**: 0D stop-bit error anywhere in the line (wins over all), 0A > 64 characters (64 is valid), 02 first token is not a keyword (also digits-only or > 8 letters), 01 bad character / unknown sub-word / missing or extra argument, 03 hex argument with > 16 digits. First error of a line wins (except 0D, 0A). Value ranges and state checks stay in rec_ctrl. After a stop-bit error the receiver waits for the line to go high (a break gives exactly one `frame_err`); a byte that follows without any idle high time is lost, the line is answered with ERR 0D anyway.
6. **ERR 0C**: the parser raises it when a line ends while the previous command is still in the output register (`cmd_valid && !cmd_ready`): the new line is dropped, one `OP_PERR`/0C is queued and issued after the previous command is taken (several dropped lines give one 0C). For the "new line before reply" rule of 2.1 to hold in full, rec_ctrl keeps `cmd_ready` low until the reply is built (WP2 does so).
7. **Message encoding** as WP2 sends it (INTEGRATION_NOTES WP2, item 2): `MK_PROF_LINE` `i=arg0[63:56] stp=arg0[31:0] dur=arg1[39:0]`; `MK_EV_S` `st=arg0[3:0] md=arg0[7:4] t=arg1[31:0]`; `MK_EV_E` `ce=arg0[7:0] cd=arg0[15:8] fl=arg0[23:16] st=arg0[27:24]`; `MK_EV_RF` `ms=arg0 ok=arg1[3:0]`; `MK_SMARTQ` `st=arg0[15:0]`; every `OK` echo from `msg_arg0` (low bits, width of the field); `MK_CFGQ/SMARTQ/DDRQ` and `MK_OK`+`OP_CFGQ/SMARTQ/DDRQ` give the same lines. **`bld` of `OK PING` is the formatter parameter `BLD_DATE`** (default `32'h20261124`), WP8 sets it per build. `MK_NONE` / unknown kind: consumed, nothing sent. Full table in the header of `rtl/rec/rec_tx_fmt.sv`.
8. **Priority**: there is one message channel, so reply/event order is rec_ctrl's. The formatter only guarantees: a waiting message goes before a pending `tel_tick`; ticks arriving while busy merge into one; a line is never interrupted. `msg_ready` is low only while a line is being *formatted* (some microseconds); the line then drains through the 2048-byte FIFO at wire speed. A `$T` is 355 bytes, so ~ 5 lines can be buffered; when the FIFO has >= 2040 bytes the formatter waits (the next `msg_ready` is delayed by up to ms).
9. **Words**: the table has 34 words (24 keywords + CLR ADD REP SET END HOLD LAST YES RT BP), the "<= 32" of 4.4 is exceeded; they are compared in parallel, no problem. `ADD` is a word after `PROF`, a number everywhere else (`READ ADD` = 0xADD).
10. `rx_valid` bytes must be >= 8 clocks apart (a UART gives >= 2000).

Required changes in `tools/recorder.py` (WP1 does not edit it): (a) `FakeDevice` `READ SID` must reply `OK READ rsid=XXXXXXXX` (it prints `OK READ SID`, which `parse_line` rejects as "bad field"); (b) `FakeDevice` `MEMTEST` should reply `OK MEMTEST mib=hhhh`; optionally add `"READ": [[], _spec("rsid:8")]`, `"MEMTEST": [[], _spec("mib:4")]` to `OK_SPEC`; (c) nothing else: all other lines of the formatter pass `parse_line(strict=True)`.

Requests to WP0 (rec_pkg, not edited): `rec_snap_t.rtd` is 16 bit but RTD3E is in us (100 ms = 0x186A0): widen to 32 bit (formatter uses `snap_q.rtd` zero extended to h8, so no change is needed in WP1 when it is widened; WP2 saturates at FFFF today). `pad_blocks`/`trunc_blocks` 16 bit are printed as h8.

## WP3 (rec_profile, rec_framer, rec_sink_chk, rec_crc128, blocks_*.hex): decisions and spec ambiguities

* **Extra files / ports.** New helper `rtl/rec/rec_crc128.sv` (CRC engine, instantiated in `rec_framer`, also tested alone against `crc_vectors.hex`). Extra output ports beyond 4.4: `rec_framer.len_reached_s`, `rec_profile.prof_end_s` (sticky levels held until `clear`/`rst`; WP2/WP8 wire them to `ui_stat_t.len_reached_s/prof_end_s`). All other ports as in 4.4.
* **crc_vectors.hex has 9 vectors, not 11** (`// vectors: 9`); `tb_rec_framer` accepts the count from the file (>= 9).
* **Burst-per-block emission (main decision).** The spec has per-beat `due` accounting, but the header beat 2 (flags TRUNC/LAST/PF, `valid`) is sent before a stop can be known, so a streamed TRUNC cannot carry its own flags. Therefore a block is emitted as a burst (1 beat/clock) as soon as its 256 beats are due (or, on stop, immediately); there is no data buffer (payload = f(pos, beat)), only descriptors G (accumulating), W (completed, waiting), E (sending). Average rate and `ts` are unchanged; the stream to `ddr_fifo` is bursty by 4 KiB. At full speed (step near 2^32) the emitter keeps up (1 clock hand-off).
* **Redefined metrics.** `bp_max_beats` / `rt_stall_max` = max backlog in beats of a completed block waiting behind the block being sent (= remaining beats of the block in flight), 0 in normal operation (<= 53 % of the bus), max 256. `rt_stall_max` is therefore not "debt inside an accepted block". BP wait (NCO frozen at a block start while `space_ok=0` or W is occupied) is NOT counted in `bp_max_beats`.
* **RT drop reasons.** At beat 0 a block is dropped if `space_ok=0` OR the waiting slot W is still occupied (the sink stalled for more than one block). BP: NCO is frozen at beat 0 for the same two reasons (no loss).
* **End of session.** stop, pf or len reached (framer ends itself, `len_reached` pulse; counted in source blocks incl. dropped): the NCO stops; the block in progress is closed as TRUNC with `valid` = payload beats already due (0..252); if there is none (boundary / dropped block in progress / nothing started) an EMPTY TRUNC (valid 0) is emitted instead - so there is always exactly one TRUNC block; then PAD up to a multiple of 32 blocks; LAST on the final block (the TRUNC itself if it ends on a multiple of 32). Worst case +32 blocks (128 KiB, spec text says 124 KiB: +1 for the TRUNC). `len` sessions also end with TRUNC + PAD (a `LEN` of whole slots is followed by one more 128 KiB slot). PF flag is added to TRUNC/PAD/LAST blocks whose beat 2 is sent after pf was seen. No stop/pf/len => `done` never rises. **D4:** `active` = NCO running (`run && !fin && !done`): it falls one clock after stop/pf/len is accepted, long before `done` (so rec_ctrl's `t1` differs from `t2`); tb_rec_framer T1 checks it.
* **NCO phase.** `acc` starts at 0xFFFFFFFF at `start` so that for any step >= 1 the first beat is due in the first clock (block 0 has `ts` = 0); rate over N clocks = floor((2^32-1 + N*step) / 2^32) beats, exact. `ts` of PAD / empty TRUNC = clock of their creation; seg/rep/`ddr_kib` of those = values at creation. `FLG_FIRST` = pos 0, `FLG_DROP` = blocks were dropped since the last accepted block (set also on a closing TRUNC/PAD).
* **Counters.** `src_blocks` = seq counter (dropped, TRUNC, PAD included); `wr_blocks` = blocks whose last beat was accepted by `m_tready`; `pad/trunc_blocks` count generated TRUNC/PAD blocks. `src_blocks = wr_blocks + drop_blocks` at `done`.
* **`rep_cnt`** (profile) is the 0-based pass number; `seg_idx`/`rep_cnt` are sampled at the beat-0 carry of a block. The profile starts 1 clock after `start` (first clock with `step_0`); `prof_end` is registered: it is visible in the first clock after the last segment (together with `step=0`). For `HOLD` there is no pulse and `prof_active` stays 1. Entries with `dur=0` are treated as 1. `prof_en` is only valid in the clock of `start` (X2b) and is latched.
* **Profile read-ahead.** The table is read ahead into an 8-entry FIFO started by `ui_clear` (and restarted when `nseg`/`rep` change), so a profile of 1-clock segments runs at full rate; the table must therefore be written before `ui_clear` of the session (true for spec 1.3: PROF commands only in IDLE). If `start` comes < ~4 clocks after `clear` the profile begins a few clocks late (tested).
* **Const mode.** `step` = `const_step` at `start` and on each `rate_upd` (RATE in RUN); `const_step` is the held output of the X2a `cdc_bus`.
* **NCO rounding.** Not decided here: the framer takes `step` as given. `tb_rec_framer` uses `round()` (280 MB/s -> 2CCCCCCD) only to build its test steps.
* **Block vectors** `sim/vectors/blocks_stop.hex` (6 natural + TRUNC valid 53 + 25 PAD, seg/rep/`ddr_kib` varying), `blocks_pf_drop.hex` (RT drops: `lost`=10, DROP flag, pf: PF on TRUNC/PAD/LAST), `blocks_len.hex` (len 8: 8 natural + empty TRUNC + 23 PAD), 32 blocks each, `sid` = 692D3A00, `$readmemh` 128-bit words MSB first (256 lines per block); all decode without errors with `python tools/rec_decode.py decode <file>`. They are rewritten by every run of `tb_rec_framer` (deterministic).

## WP9 (tools/recorder.py, rec_decode.py, power_table.tcl, crc_vectors.hex): spec ambiguities

1. `$T` length: spec 2.5 says ≈290 chars (3.1 ms); the listed fields with names give 355 chars (3.9 ms at 921600; `TEL 000A` = 39 % of the line). recorder.py parses by the field list, not by length.
2. NCO step rounding: formula says `round()`, but example 2.7 prints `2CCCCCCC` for 280 MB/s (that is floor; round gives `2CCCCCCD`). recorder.py uses `round()`; error is 1 LSB (0.4 B/s). Fixed-width hex is always sent (`PROF ADD 00000000 0002FAF080`), not the shortened form in the example.
3. Widths not given in the spec for `!RR` (all fields except `dur=h16`; `sid` assumed h8), and for the reply fields of `OK READ/FORMAT/MON/MEMTEST/DTEST`. Parser checks only the listed ones; the key order for `!RR` is taken from 2.6. `!RV` first field `vb` assumed h12 (as in `$T`). 2.7 example shows `!RP ... tot=` which is not in 7.2; unknown extra keys in `!R*` events are accepted and kept.
4. `!RV ok=h10`, `!RP ok=h1`, `!RR lat=h8` vs `!RP lat=h1`: same key, different meaning per message; the parser keys by message name.
5. `OK SMART`: spec gives `OK SMART sm=h4` (set) and the 17-field form (`SMART?`); recorder.py accepts exactly these two. In the 17-field form `dur`/`duw` are Data Units Read/Written (NVMe unit 512 000 B), `ok` = log_cnt-like counter; `tk` is in kelvin.
6. `rng` ($T) may be transiently negative as a u32 difference; shown as unsigned.
7. Power estimate: total = `p_static_W + p_dyn_W` (the rail columns are informational, not added). md → table mode: 0 IDLE, 1/2/6/7 REC, 3 READ, 4/5 MON. Rate = actual NCO rate from `stp`; for READ (no `stp`) the table's single READ rate is used. Tj = XADC `xt`. Without `fpga/power/power_table.csv` the CSV gets empty `p_fpga_est_W` and `p_note=NO_POWER_TABLE`.
8. `power_table.tcl` was NOT run (no Vivado here): data-path net patterns (`*u_rec_framer* *u_ddr_fifo* *u_data_ring* *u_rec_verify* *u_vrf_tap*`) are guesses until WP8 fixes the hierarchy; override via env `PT_DATA_NETS`. The report_power parser expects the usual Vivado 2025.2 "Power Supply Summary" table. Needs a first real run to check the CSV.
9. `sim/vectors/crc_vectors.hex` format (for `tb_rec_framer`, `$readmemh` into a 128-bit memory): N=9 vectors x 256 lines; lines 0..254 = beats 0..254 of a 4080-byte message (128-bit hex, MSB first, byte 0 = bits[7:0]); line 255 = `{96'h0, crc32}`. `//` comments are allowed. Regenerate: `python tools/rec_decode.py gen-crc-vectors`.
10. `blocks_*.hex` (WP3) format is not defined in the spec; `rec_decode.py decode` accepts raw binary or `$readmemh` text with 8/32/64/128-bit words (MSB-first words, little-endian memory), `//` comments and `@addr` lines ignored. If WP3 uses another layout, tell WP9.
11. Line terminator sent to the board: LF (`--eol cr|crlf` available). If `rec_cmd_parser` treats CR+LF as two EOLs, CRLF would yield an empty line; LF alone is the safe default.
12. Fake device (`--fake`) models protocol replies only (virtual clock, no timing/DDR/SSD behaviour); it is not evidence for the RTL.

## WP4 (ddr_fifo, ddr_memtest, mig_app_model, MIG .prj / mig_ip.tcl): notes and spec ambiguities

* **Ports** of `ddr_fifo` = spec 4.4 letter for letter (`app_rd_data_end` is accepted and unused). `ddr_memtest` is instantiated inside `ddr_fifo` (port list: `clk, rst, start, mib, init_calib_complete, busy, done, err_cnt, first_err_addr` + the app signals, see its header).
* **Memory layout.** Staging and output RAM are 256 x 512 (16 KiB each; `sdp_ram`, 4 RAMB36 each = 8 RAMB36 total) instead of the 128 x 1024 + packer of the spec text: packing 2 x 128 -> 256 is done in front of the staging RAM, unpacking behind the output RAM. Same capacity, same budget. Beat order: first 128-bit beat = bits [127:0] of the 256-bit word. An odd last beat (< 2 beats) or a tail < 64 words (2 KiB) stays in the staging RAM forever (only whole batches move; `idle` stays 0): all session volumes must be multiples of 2 KiB (PAD in the framer guarantees it).
* **Counter semantics (spec silent).** `wr_bytes / rd_bytes` = bytes accepted at `s_axis` / delivered at `m_axis` (stream level, not DDR level), cleared by `clear` (not by anything else but `rst`); `fill_bytes = wr_bytes - rd_bytes` = everything inside (staging + DDR + output RAM); `fill_max_bytes` = maximum of `fill_bytes` since `clear`. WP2/WP3: `ddr_fill_kib` for the framer and `DDR?` (`ddr`, `ddrm`) should be taken from these. If a DDR-only fill is wanted, tell WP4.
* **space_ok** (registered, 1 cycle old) = calibrated AND not clearing AND no memtest AND DDR window free >= 8 KiB (counted in whole 2 KiB batches that are already written/read-reserved, i.e. data still in staging is NOT counted as DDR fill) AND staging free >= 8 KiB (256 words). Guarantee (tested): a 4 KiB block admitted with `space_ok=1` at its first beat is accepted without any `s_tready` stall, also when the sink is stopped for ever.
* **clear.** Stops command issue at once, waits for all MIG read responses in flight (dropped), then zeroes pointers, counters, maximum, address pointers (both back to word address 0). Measured: <= 30 cycles (300 ns) with read latency 30 (spec limit 2 us). `s_tready = 0`, `m_tvalid = 0` (also in the cycle of `clear`) and `space_ok = 0` while clearing; beats accepted at `s_axis` in the cycle of `clear` are discarded (WP2 must also clear the framer with the same pulse; `src_*` must not send during the clear). **clear also aborts a running or pending memtest (audit D5):** `ddr_memtest.abort` = `clear`; it stops issuing, waits for its own reads in flight, then `mt_busy=0`, `mt_done` stays 0, `mt_err_cnt/first_err_addr` kept; the FIFO engine gets the MIG port back only after that (`idle`/`space_ok` rise ~60 cycles after the clear at most). Tested (tb_ddr_fifo T6c, tb_ddr_memtest).
* **size_mib** is sampled only while `idle = 1` (module empty). It must be stable before the first beat of a session (WP2 loads it with `rec_cfg_t` in IDLE; `ui_clear` at session start also rewinds the address pointers). Window end = `size_mib << 18` words; `0` is treated as 1 MiB; pointers wrap with `>=`, so a smaller window after a larger one without `clear` is still safe.
* **MIG handshake.** `app_en`, `app_wdf_wren`, `app_wdf_end` are combinational: asserted only in a cycle in which `app_rdy` (and for writes `app_wdf_rdy`) are 1, and a write command and its 256-bit word go out in the SAME cycle. Therefore "hold until ready" cannot be violated, no write data is left dangling by a `clear`, and the MIG write FIFO never has to be read ahead. Consequence: `app_rdy` / `app_wdf_rdy` -> `app_en` / `wren` is a combinational path inside `ui_clk` (100 MHz, a few LUTs) - WP8 to check timing in the real build. Commands are issued in batches of 64 (2 KiB); read data goes straight to the output RAM (the MIG has no back pressure), room is reserved when the read batch is started.
* **Arbitration (M10).** Decision once per batch (1 idle cycle between batches, 64/65 efficiency). Both sides ready -> alternate; otherwise whichever is ready. In the model without pauses: 0.982 beats/cycle through the FIFO with both sides saturated (1.57 GB/s per direction, 3.1 GB/s DDR traffic; spec 5.4 requires 1.7 GB/s). The real MIG (refresh, row misses, bank conflicts - sequential 2 KiB bursts hit the same row per bank) will be lower; spec 5.4 estimates 80-85 %.
* **Memtest.** `mt_start` is ignored unless `init_calib_complete`; the test starts when the FIFO engine is between batches with nothing in flight (`mt_busy = 1` from the pulse on). It DESTROYS the DDR contents. `mt_done` is sticky (cleared by the next start), `mt_err_cnt` counts mismatching 256-bit words of both passes (an error at one address in both passes counts twice), `mt_first_err_addr` = `app_addr` (29-bit word address, multiple of 8) of the first mismatch. Pass 0: lane i of word at address A = {3'b0, A[28:3], i}; pass 1: eight independent 32-bit Galois LFSRs (x^32+x^22+x^2+x+1), one step per word. Duration: ~190 k cycles per MiB with 20 % random ready drops in the model (~2 ms real time per MiB, ~2 s for 1 GiB).
* **Model `mig_app_model` knobs** (variables, set hierarchically; initial values from parameters): `calib_delay, calib_fail, rd_latency, rd_lat_jitter, rdy_drop_pct, refresh_period, refresh_len, bw_limit_pct, inject_err_addr, track_runs`; statistics `wr_cmds, rd_cmds, proto_errors, unwritten_reads, short_runs (call finish_runs() first), injected, max_addr`. `UI_PERIOD_PS` / `JITTER_PS` are parameters. The model has no DDR3 pins; the real MIG additionally has `sys_clk_i`, `sys_rst` (active low), `device_temp` (output, unused).
* **Test volumes are scaled down** (limit 2 min per test, the run takes ~20 s): 4.3 MiB random-backpressure stream instead of 64 MiB (>= 4 wraps of the 1 MiB window), 810 us read stall instead of 81 ms (0.81 ms x 280 MB/s = 227 KB < the 1 MiB window; the stall is 100x shorter, the data volume scaled with it). The 1024 MiB window is exercised by data transfer and an address bound only: its wrap (after 1 GiB of traffic) is not simulated - the same comparator is covered by the 1/2 MiB windows.
* **MIG .prj (hand-written, accepted by `create_ip`/`generate_target` of Vivado 2025.2 without a single warning; MIG normalises it to the same values).** Values not fixed by the spec: `VccAuxIO 1.8V` (DDR3-800), `BankMachineCnt 4`, `tFAW 50 ns`, `tRRD 7.5 ns` (x16 / 2 KB page parts; the template with x8 parts had 40 / 6), `mrCasLatency 6`, `CWL 5`, `LowPower_En ON`, `UIExtraClocks 0`. `InternalVref = 1` (spec Q3 default: no ALINX demo available here) -> generated XDC has `INTERNAL_VREF 0.750` on bank 35 only (bank 34 holds only address/control: 27 pins; bank 35 the 44 data pins) - to be confirmed against the board schematic (Q3). `MemoryDevice` is written as `MT41J256m16XX-125` (MIG's own spelling). Q4 (part marking) unchanged.
* **Hook for WP8.** `create_project.tcl` should `source fpga/scripts/mig_ip.tcl` after it has defined `ip_dir`: IP lands in `$ip_dir/mig_ddr3`, any failed check is a Tcl `error`. Standalone (`vivado -mode batch -source fpga/scripts/mig_ip.tcl`) it creates a scratch project in `fpga/build/mig_check` and exits 0/1. The generated MIG is `mig_ddr3` with ports `sys_clk_i` (200 MHz, from the BUFG `link_clk_out`), `sys_rst` (active low), `device_temp_i[11:0]`, `ui_clk`, `ui_clk_sync_rst`, `init_calib_complete`, `app_*`; no `clk_ref_i`. `sys_clk_i` must be constrained by WP8 (`create_clock` is commented out in the generated XDC because the clock is not a port).
* **MIG tie-offs for WP8.** In the generated `mig_ddr3` (default, no `SKIP_CALIB` define) the `calib_tap_*` ports do NOT exist; they appear only if `` `define SKIP_CALIB `` is set in mig_ddr3.v, and then must be tied: `calib_tap_load` = 1'b0, `calib_tap_addr[6:0]` = 7'd0, `calib_tap_val[7:0]` = 8'd0, `calib_tap_load_done` = 1'b0 (`calib_tap_req` output open). Everything else: `sys_rst` = `mig_sys_rst_n` (active low, POR only), `device_temp_i[11:0]` = xadc temp via X14 (`device_temp[11:0]` output open), `app_sr_active/app_ref_ack/app_zq_ack` outputs open; `app_sr_req/app_ref_req/app_zq_req`, `app_wdf_mask` are driven by `ddr_fifo` (0). `ddr3_*` pins = top ports; `ui_clk`/`ui_clk_sync_rst` feed the ui domain (`ui_rst` = `ui_clk_sync_rst` OR rec_rst, synchronised).
* **Sanity with the Micron model** (`sim/scripts/run_mig_sanity.tcl`, outside the regression): PASSED on 2025.2 (example-design testbench, Micron `ddr3_model` x16 x2, `SIM_BYPASS_INIT_CAL=FAST`, 400 MHz: write/read calibration done at 105 us, then 50 us of traffic with compare, `TEST PASSED`; ~7 min wall time).

## WP5 (nvme_admin Get Log Page, core / top pass-through, SSD model): notes and spec ambiguities

* **Port names (spec 4.6 gives only the tap names).** Core and top export: input `log_req` (default 0); outputs `log_busy, log_done, log_err` (done/err are 1-cycle pulses), `log_smart[SMART_W-1:0]`, `log_cnt, log_err_cnt, log_status` (16 bit), `rtd3e_us[31:0]`; tap `tap_wr_en, tap_wr_addr[31:0], tap_wr_data[127:0], tap_wr_be[15:0], tap_slot_lba_flat[N_SLOTS*64-1:0], tap_verify_mode`. Top additionally has `stat_beats_in[63:0]` and `stat_seq_state[3:0]` (M17) and parameter `VERIFY_INTERNAL` (default 1). Core `log_req` is not synchronised: it must already be a `user_clk` pulse (WP2 `rec_cdc_bridge` `log_req_u`).
* **Tops.** `kc705_top` / `ax7a200b_top` need no edit (new inputs default to 0, new outputs unconnected). Pre-existing, not WP5: `xvlog -sv` of `rtl/board/ax7a200b_top.sv` reports "span_cyc used before its declaration" (line 226) - Vivado synthesis accepts it, xsim does not; the file is not in any xsim list.
* **Core gate (M2).** `log_req` reaches `nvme_admin` only while `status_seq_state` is RUN (5) or DRAIN (6). The spec text for 4.6 says the same; `rec_ctrl` must in addition stop requesting after STOP/PF (if a log is already running at PF, `nvme_admin` finishes it first, then runs the latched shutdown - flag `lov` in `!RP` is `log_busy` at `t0`).
* **log_err on a bad CQE.** A log CQE with wrong CID or status != 0 is still consumed (CQ head doorbell is rung, `log_status` = its status) and only then `log_err` is raised: otherwise the controller would see an unconsumed CQ entry and the CQ would eventually fill up. A failed BAR0 doorbell (SQ doorbell) leaves the SQE pending in the controller; the CID counter is advanced anyway - a later CQE with that CID would be reported as a CID mismatch (`log_err`) and consumed. Not tested (the model's strict CID/doorbell checks make the SQ-doorbell error test unrepresentable); the CQ-doorbell error is tested.
* **CID.** `cid` is incremented after every log (success, failure, timeout) so that the CID of an abandoned command never collides with the next command. `cmd_seq` is not touched.
* **stale_cid.** Only one abandoned CQE is tracked (`log_dis=1` after the first timeout prevents a second). `stale_v/stale_cid/log_dis/shn_pend` and `log_cnt/log_err_cnt` are cleared by `start_init`; `log_cnt/log_err_cnt` are NOT cleared by `start_shutdown`. `log_smart` and `rtd3e_us` are cleared only by reset.
* **Late CQE absorption** is done in any poll (init, log, shutdown) when `stale_v` and the CQE CID equals `stale_cid`; the absorbing CQ doorbell does not restart the timeout counter of the command that is being waited for.
* **start_shutdown latch.** `shn_pend` is set only while `in_log`; a `start_shutdown` that arrives in the same cycle as `log_req` in S_IDLE wins (the log is not started). Because of the latch `shutdown_done`/`shutdown_timeout` are masked in the cycle in which a pending shutdown is taken.
* **Identify Controller RTD3E.** Extra `ex_step` reads beat 5 (bytes 80-95) between the MDTS beat (4) and the SQES beat (32); the number of `ident_ram` reads of Identify Controller grows from 2 to 3 (fail_step order unchanged).
* **SSD model knobs (names).** `smart_cw/temp/spare/used/dur/duw/pc/poh/unsafe/media/wtt/ctt/ts1`, `log_status` (15 bit, no data transferred when != 0), `log_delay_cycles` (delay before the CQE, data already written), `stall_at_cmd` (0-based index of the I/O *data* command, Write or Read; Flush is not counted) / `stall_cycles`. The stall is global: no SQE fetch and no command proceeds past its latency step until the pause is over; commands already transferring data finish. `n_log` counts completed logs. Log supports NSID 0/1/FFFFFFFF, LID 02h only (other LID: Invalid Field), no log page offset, NUMDL <= 127 (shorter transfers write fewer bytes).
* **tb_nvme_admin / tb_admin_rams** now put the real `req_mux` between `nvme_admin` and the controller model (port 1 = doorbell generator) and the model keeps its CQEs in an ordered queue with deadlines; every old test passes unchanged. `.f` files of both tests gained `rtl/pcie/req_mux.sv`.

## WP7 (xadc_mon) — notes

## WP6 (vrf_tap, rec_verify): notes and spec ambiguities

1. **Test vectors are NOT WP3's.** `sim/vectors/vrf_blocks.hex` (75 blocks x 256 x 128 bit, `$readmemh`, MSB first) is made by `tools/gen_vrf_blocks.py` with `tools/rec_decode.py build_block` (self-checked by `decode_block`). Index = pos: 0..63 clean chain (sid C0DE0001, lost=3 from 10, TRUNC 58, PAD 59-63, LAST 63), 64-74 one corruption each, 69 = copy of 62. To be cross-checked against WP3's `blocks_*.hex` (same layout is accepted by `rec_decode.py decode`).
2. **Extra output `mvp_flags[7:0]`** on `rec_verify` (not in 4.4): `flags` of the max-valid block (bit 1 = LAST). `vrf_res_t` has no field for "chain ends with LAST" (spec 3.2: no LAST = recording cut). Can stay unconnected; decide if rec_ctrl/!RV needs it.
3. **Context key.** 3.3 says "context per slot" but the tap carries no slot number. `rec_verify` keeps `N_CTX=8` block contexts indexed by `pos[5+:3]` (128 KiB = 32 blocks per slot), so concurrently read slots (consecutive 128 KiB chunks) do not collide. Commands that are not 128 KiB aligned only lead to `ooo`/`bad`, never to a false OK. Parameters `N_CTX`, `CTX_SHIFT`.
4. **Counter definitions the spec leaves open** (header of `rec_verify.sv`): `vb` = byte-enabled bytes of all beats; `ve` = beats with any error; `bad` also counts a block abandoned by a new beat 0 in its context (+`ooo`); `crc` = CRC mismatch (also for all-zero stale blocks: they count in `bad` and `crc`); `ooo` also counts misaligned addresses; `pad` counts OK PAD blocks only; `fbp` = min pos of a bad (closed or abandoned) block; a block cut by the end of the stream is neither ok nor bad; `feb` = DW index (0..3) of the first mismatching DW, `fep` = {pos[31:0], j[7:0]}. Partial (be != FFFF) header/trailer beat -> block bad; partial payload beat -> `prt`, bytewise compare, CRC not checked.
5. **`ovf`.** `vrf_tap.ovf` = sticky flag from user_clk through `cdc_sync`; it is cleared when `enable` (= tap_verify_mode) is 0, so rec_ctrl must have `verify_mode`=0 between READ sessions (otherwise the flag from a previous READ stays and `res.ovf` re-sets after `ui_clear`). `rec_verify.res.ovf` is sticky until `clear`. Overflow loses beats, the results are invalid.
6. **Rates.** `rec_verify` accepts 1 beat/ui_clk (`s_tready` = ~rst), latency 8 clk. The FIFO (512) overflows only if the tap delivers > ~0.8 beat per user_clk for > ~2500 beats (tb: bursts of 256 beats + 80 idle never overflow at 100.3 MHz).
7. `res.vb`, `ve`, ... are cleared by `clear` and `rst`; `lbads` is used as is (9..12, anything else = 9). START_LBA uses bits [31:0] only. Timing in `rec_verify` S8 (CRC128 + context mux in one stage) not synthesized here: risk for 100 MHz, split the context read/CRC if WNS fails.

## WP2 (rtl/rec/rec_ctrl.sv): decisions and spec ambiguities

1. **Parser contract (WP1 must match).** `cmd_sub`: MODE 0 RT / 1 BP; PROF END 0 HOLD / 1 STOP. Args: TEL/SMART/RATE/LEN/SID/DDRSZ/PROF REP/READ N/READ SID/MEMTEST = `arg0`; PROF ADD `arg0=step arg1=dur`; PROF SET `arg0=i arg1=step arg2=dur`; MEMTEST without argument = `cmd_nargs==0`. Value ranges (TEL, SMART, DDRSZ, PROF, READ N, MEMTEST, widths > 32/40/16 bit -> ERR 03) are checked in rec_ctrl, the parser does syntax only. `OP_PERR` is forwarded as `MK_ERR` with `cmd_err` (0 -> 01); ERR 0A/0C/0D therefore arrive as `OP_PERR`. Unknown op -> ERR 02. `cmd_ready` is a register: low while a reply is built / PROF? runs / message FIFO is > 8 deep.
2. **Message encoding (WP1 `rec_tx_fmt` must match).** OK: `msg_code`=op, `arg0`=echo value (sid, step, i, n, bp ...). ERR: `msg_code`=code. `MK_PROF_LINE`: `arg0={i[7:0],24'h0,step}`, `arg1=dur[39:0]`. `MK_EV_S`: `arg0={md[3:0],st[3:0]}`, `arg1=t_ms` (values in args, not in `snap`, because the FIFO may delay the line). `MK_EV_E`: `arg0={st[3:0],fl,cd,ce}` (st = state at the event; st=8 for the CORE_RST timeout). `MK_EV_RF`: `arg0`=ms, `arg1`=ok (core_stat has no `format_ms`; ms = t_ms(DONE) - t_ms(start)). `MK_SMARTQ`: `arg0[15:0]`=log_status. For `MK_EV_RR/RP/RV/RF/RM/RD` `snap` shows the result image latched at DONE (RES? repeats it); all other kinds see the live image. `rtd` in snap is 16 bit (spec 7.2 says h8): saturated at FFFF. `!RP t1..t6` are 64-bit link clocks (h16). `lpos = wr_blocks - 1`.
3. **Phase measurement (7.2).** t1 = first fresh ui snapshot with `src_active==0` after the stop request (WP3: `src_active` must fall when stop/pf is accepted; if it stays high until `done`, t1 = t2); t2 = `src_done`; t3 = moment `ctrl_stop` is set; t4/t5/t6 = first fresh snapshot with cs in {FLUSH,SHUTDOWN,DONE} / {SHUTDOWN,DONE} / DONE. Phases that ended before `t0` (PF after STOP) read 0; unseen phases take the value of the next seen one; PF in BRINGUP: t1..t3 = 0. `pnd/prg/pdd/pad` use the snapshots one clock before `t0`.
4. **Capacity / len_blocks.** capacity in 128 KiB slots = `nsze >> (17-lbads)`; `len_blocks = 32*min(len, cap-1)` (one slot of headroom for TRUNC+PAD, spec 3.2), `len=0` -> `cap-1`; the "ёмкость" row of table 1.3 is therefore covered by `len_reached_s`. If `nsze==0` at RUN the LEN value is passed unchanged. `READ END`: `verify_cmds = cap slots`, loaded while in BRINGUP as soon as `nsze != 0` is seen (core must not keep a stale `nsze` across CORE_RST; until then `verify_cmds=0` = unlimited, harmless because the engine starts only in RUN). `READ LAST`: `verify_cmds = ceil(wr_blocks/32)` of the last REC/PF (stored at RELEASE, also for errored sessions).
5. **Ordering towards the ui side.** `step_load` is sent at session start (REC, DTEST) and on every accepted RATE; `start_load` at RUN; a pending `src_stop/src_pf` waits 64 clocks after `start_load` (X1 vs X2b can overtake each other); a STOP/PF before `start_load` cancels the start. LOCAL: `ui_clear`, 1024 clocks, then `mt_start`/`dtest_start` (assumes `ddr_fifo` clear <= 2 us). `mt_done` must stay 1 until `ui_clear` (X4 would miss a pulse). MEMTEST STOP aborts by `ui_clear`; DTEST STOP -> `src_stop`, ends on `src_done && ddr_idle` (>= 512 clocks later).
6. **Command/state rules chosen where 2.3 is silent.** STOP only in BRINGUP/RUN/LOCAL (SRC_STOP, CORE_STOP, RELEASE, IDLE -> ERR 04, keys are ignored silently). PFAIL in SRC_STOP/CORE_STOP only for `md=REC` (late PF); a second PF, PF in RELEASE/LOCAL/IDLE -> ERR 04; PF in READ/MON/FORMAT acts as STOP (md unchanged, no !RP). Any refused command in CORE_RST/ERROR -> ERR 06, else 04; `REC/READ/MEMTEST/DTEST` check `calib && ui_ok && ui_age_ok` (-> 05) after the state check, `REC PROF` empty -> 08 and `READ LAST` without record -> 0B after that. `OP_NOP` is ignored.
7. **Defaults.** step `10000000` (100 MB/s), TEL/SMART `03E8`, DDRSZ `0400`, REP 1, PROF END STOP, RT mode. SID: `SID x` is used once, otherwise +1 per REC (first REC after reset = 1); `READ SID` is used once, default = SID of the last REC. KEY1 / `vio_start` = REC, with `prof_en=1` when the profile is not empty (`vio_verify=1` -> READ LAST). First `log_req` comes `SMART` ms after RUN entry; skipped while `log_busy` or snapshot stale.

First route: free_clk (link_clk 200 MHz) -5.05, clk_pll_i (ui_clk 100 MHz) -3.09, userclk2 -0.16, cdc_bus bus skew. Changes (behaviour at the ports unchanged, only latency added):
- `rec_ctrl`: command path is now accept -> operand flags (`f_*`) -> decode (`x_err_q`) -> state check (`moved_q`: state / mode / calibration moved since the decode -> decode again) -> execute: a command takes ~4 clocks longer. `go_*` / `ev_*` requests are registered (state machine acts 1 clock after the command). Message FIFO: both push ports go through staging registers (`sa_*`, `sb_*`), plus a pre-stage before `msg_*`; `mq_r` flag selects `snap` (result image) from registers; `b_room` assumes port A pushes (conservative). `!S` events, `prog_q` clear and `!E` data use `st_prev_q` / `s_chg` (one clock after the state change; `!S` carries `md_q/st_q` then). Result images (`res_q`) are captured one clock after DONE / LOCAL end from registered helpers (`rp_pad_q`, `rp_lpos_q`, `ldur_q`; `rcap_*`), `ui_clear` of a MEMTEST end follows the image. Phase times / duration: `tdiff_q`, `tgt_q`, `dur_*_q` registered, fin sequence has one wait step (steps 6..13). `do_capture` (t0 / rp_pnd...) acts one clock later. Core status decode (`cs_*_q`), link/watchdog error (`lw_err_q`, `idle_err_q`), `prog_to_q`, `uwd_to_q`, `nsze_nz_q`, `vc_last_q` are registered (1 clock stale). `prog_q` counts only in SRC_STOP / LOCAL after STOP (the only places that read it).
- `rec_verify`: 10 stages. S8 pre-decode (header / trailer / version compares, `seq == pos + lost`, CRC contribution of the data `crc32_128(0, d)`, first mismatching DW, beat class flags); S9 context read-modify-write with the CRC update `crc' = crc32_128(crc, 0) ^ cd` (crc32_128 is linear) and side-by-side compares against the unmodified context; S10 result counters from registered event flags (`e_*`). `res` follows the last beat by 3 more clocks than before.
- `ddr_memtest`: `app_rd_data` is compared per 32-bit lane into registers, the error counter and `done` work one clock later (`fin_q`; `busy` stays 1 until `done`).
- `cdc_bus`: `hold_q` has no reset and no `src_rst` in its enable (a stray load while `src_rst` is active is harmless: `hold_q` is only used after a toggle, which is gated by `src_rst`); `busy_q` / `chg_q` carry `max_fanout 24`.
- `hostmem_writer` (shared core): `fits()` written as `addr >= base && addr + n <= base + size` (one adder less; same function).
- `ax7a200b_rec_cdc.xdc`: `set_bus_skew` on `u_cdc_bus*/hold_q -> dst_data_q` removed (hold-and-toggle: per-bit skew is irrelevant, `set_max_delay -datapath_only 5.0` stays); kept for the gray pointers.
- Left as is: `report_cdc -severity Critical` rows for the PCIe core (clock mux false paths, `u_sequencer/cur -> u_cdc_sync_st` comb. before synchroniser CDC-10, reset fan-out CDC-11) - not touched.
