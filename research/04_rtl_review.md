## 1. BLOCKER

### B1. No top level that can produce a bitstream; board pins are still placeholders

- **Where:** `fpga/scripts/create_project.tcl:139` (`set_property top nvme_host_top [current_fileset]`);
  `fpga/constraints/kc705_fmc_m2.xdc:69-84` (all user pins commented out); `nvme_host_top.sv:33-66` (port list).
- **Problem:** `nvme_host_top` is the implementation top. It has about 355 non-GT user ports:
  `s_data_tdata[127:0]`, `stat_bytes_done[63:0]`, `stat_cmds_done[63:0]`, `stat_cmd_errors[31:0]`,
  `stat_max_latency[31:0]`, `status_*`, `ctrl_*`, `board_rst_n`, `data_clk` and `user_clk_out`. Only `sys_clk_p/n` and
  `pcie_perst_n` have a `PACKAGE_PIN`. In particular `board_rst_n` (the only reset of `link_bringup`) has no pin.
- **Why it matters on hardware:** `write_bitstream` stops on DRC NSTD-1 and UCIO-1 (unspecified I/O standard and
  unconstrained ports), so `build.tcl bit` cannot finish. Even if those checks are waived, `board_rst_n` would float and
  the start/stop/status signals could not be reached.
- **Also verify before the first run.** `sys_clk_p` is placed on C8/C7, and the XDC now LOCs the lanes at
  `GTXE2_CHANNEL_X0Y12..15` (lines 61-64). A GTX can only use an MGTREFCLK of its own quad or of the quad directly above
  or below it. Confirm in UG810/the FMC schematic that C8/C7 is MGTREFCLK0/1 of quad 118 (or 117). If it is not,
  `place_design` fails on the reference-clock routing.
- **Fix:** add `fpga/rtl/kc705_top.sv` (or `board_top.sv`) that instantiates `nvme_host_top`, and make it the
  implementation top. It should:
  - drive `ctrl_*` from a VIO, watch the status in an ILA, and feed `s_data_*` from a pattern generator (LFSR or counter, which also gives a check on readback);
  - take `board_rst_n` from the inverted KC705 CPU_RESET (AB7, LVCMOS15, active high);
  - bring only LEDs and the reset out to pins.

## 2. MAJOR

### M1. `m_axis_rx_tready` is a 19-level combinational path into the IP's soft RX pipeline; timing is likely to fail after routing

- **Where:** `rtl/pcie/pcie7x_rx_adapt.sv:121` (`int sof_lane, a_hi, b_hi, a_first, a_n, cnt;`), `:144`, `:166-173`,
  `:222-225`:
  ```systemverilog
  assign rdy_all = (!hdr_push_i || hf_s_tready) && (!eof_push_i || ef_s_tready) && (!pl_push_i  || dw_s_tready);
  assign m_axis_rx_tready = !m_axis_rx_tvalid || rdy_all;
  ```
  `dw_shift.sv:85` `assign s_tready = can_load && (!flush_q || prime_new);` (where `prime_new` depends on
  `s_shift/s_tlast`, i.e. on the splitter output).
- **Evidence:** `fpga/build/reports/synth_timing_summary.rpt:7925`. The worst userclk2 setup path runs from
  `u_core/u_rx_adapt/hdr_wait_q_reg` to `u_pcie/.../axi_basic_top/rx_inst/rx_pipeline_inst/m_axis_rx_tuser_reg[19]/D`.
  It has a slack of +0.679 ns and 19 logic levels (CARRY4=9), with route delay estimated on unplaced nets. The 9 CARRY4
  levels come from the 32-bit `int` comparisons in the splitter, such as `int'(eofdw) < sof_lane` and `a_n < int'(pl_rem_q)`.
  The path then continues through `rx_null_gen` inside the IP: `m_axis_rx_tready` does not end at the hard block but
  enters 5 more LUT/CARRY levels of the IP's `axi_basic` shim.
  The next path (+1.03 ns, 12 levels) goes from the header-FIFO LUTRAM through `tlp_rx_demux` routing to the `fits()`
  34-bit compares in `hostmem_writer` (endpoint `p_fbe_reg/CE`).
- **Why it matters:** post-route delay on a path that crosses the IP boundary and spans the die is usually 1-2 ns worse
  than the post-synthesis estimate. A setup failure on `tready` corrupts the RX stream intermittently: beats are lost or
  duplicated at the core boundary. Simulation cannot detect this.
- **Fix (both parts recommended):**
  1. Put a register slice directly at the core side, so that `m_axis_rx_tready` comes from a flip-flop. The splitter
     then works on the slice output.
     ```systemverilog
     axis_skid #(.W(128), .UW(22)) u_core_skid (.clk, .rst,
       .s_tdata(m_axis_rx_tdata), .s_tkeep(m_axis_rx_tkeep), .s_tlast(1'b0), .s_tuser(m_axis_rx_tuser),
       .s_tvalid(m_axis_rx_tvalid), .s_tready(m_axis_rx_tready),     // registered ready
       .m_tdata(c_tdata), .m_tkeep(), .m_tlast(), .m_tuser(c_tuser), .m_tvalid(c_tvalid), .m_tready(c_tready));
     ```
     The PG054 rule (tready may drop at any time) still holds, and `rx_np_ok` is unaffected.
  2. Replace the `int` locals in the splitter with sized types (`logic [2:0]` for lanes and counts,
     `logic [PLW-1:0]` for `pl_rem`). Also decode `hd_ok` in `hostmem_writer` from a registered header, or
     precompute `fits()` with 13-bit offsets (all regions are smaller than 8 KiB).

### M2. A second run (start released, then asserted again) uses stale `done`/`fail` levels and skips stages

- **Where:** `rtl/nvme/host_sequencer.sv:90-94` (start pulses on state entry), `:131-150`:
  ```systemverilog
  ST_ENUM: begin
    if (enum_fail) begin ... end else if (enum_done) begin cur <= ST_RPCFG; end
  ```
  The submodules clear their level outputs only at the clock edge that samples the start pulse:
  `pcie_enum.sv:254-256` (`if (start && !start_q) begin done <= 1'b0; fail <= 1'b0;`), `rp_cfg_init.sv:122-123`,
  `nvme_admin.sv:416-418`.
- **Problem:** in the cycle where the sequencer enters ENUM/RPCFG/ADMIN_INIT, `enum_done`/`rpcfg_done`/`init_done`
  (or `init_fail`) still hold the result of the previous run. The sequencer therefore moves to the next state one cycle
  later, while the submodule is only just starting. Consequences:
  - After DONE, the next start goes ENUM → RPCFG → ADMIN_INIT → RUN in 3 cycles.
  - `pcie_enum` and `nvme_admin` then drive command port 0 at the same time. They are combined as
    `p0_req_valid = en_req_valid | ad_req_valid` (`nvme_host_core.sv:214-218`), so their requests are corrupted.
  - After an `init_fail`, a retry goes straight back to ERROR.
  - The write engine supports only one run per reset (`nvme_write_engine.sv:58-59, 317-318`).
  The first run after reset works, which is why the testbenches pass. This contradicts `host_sequencer.sv:20`
  ("DONE … Back to IDLE once `start` is released"), which implies that runs can be repeated.
- **Why it matters:** an operator who restarts a recording without a board reset sends interleaved config and MMIO
  TLPs to the SSD and can end up with a half-initialised controller.
- **Fix:** ignore completion inputs in the entry cycle, i.e. evaluate `*_done`/`*_fail` only when `!entered`. That is
  enough because every submodule clears its level at that same edge. In addition, either add a `restart` input to
  `nvme_write_engine` (reload `next_lba`, clear `started`, `flush_*`, `lba_range_err`), or make DONE and ERROR terminal
  until reset and document that.

### M3. A link drop silently restarts the whole bring-up and recording from `START_LBA`, overwriting data already on the SSD

- **Where:**
  - `link_bringup.sv:299`: `S_READY: if (!lnk_up_s) next_state = S_HOLD;` This performs a PERST# cycle and asserts `sys_rst_n=0`.
  - Generated IP `pcie_7x_0_core_top.v:1061`: `assign sys_or_hot_rst = !sys_rst_n || ...`. This asynchronously asserts
    `user_reset_out`, which stays high until the next PHY link-up (`:1101`).
  - `nvme_host_top.sv:179`: `.user_rst(user_reset)` resets all of `nvme_host_core`.
  - `host_sequencer.sv:121-126`: `ST_IDLE: if (start) ... cur <= ST_LINK;` uses the **level** of `ctrl_start`.
  - `nvme_write_engine.sv:317`: `if (!started) next_lba <= start_lba;`
- **Problem:**
  1. `E_LINK_LOST` (`host_sequencer.sv:115-118`) is visible for only a few cycles. Then `user_reset` clears
     `error_code` to `E_NONE`.
  2. Once the link retrains and `link_ready` returns, the still-high `ctrl_start` restarts enumeration, init and RUN.
     `next_lba` is back at `START_LBA`, so new data overwrites the start of the recording. Data in the ring at the
     moment of the drop is lost without any indication.
- **Why it matters:** for a CPU-less recorder this is silent corruption of what was already recorded.
- **Fix:**
  - Start a run only on a rising edge of `ctrl_start` that is seen in IDLE.
  - Keep a sticky `link_lost` / `run_aborted` flag in a domain that `user_reset` does not clear. The `link_clk` domain
    inside `link_bringup`, reset only by `board_rst_n`, works. Export it to the top.
  - Optionally, in `link_bringup` go from READY to a latched FAULT state (PERST# kept asserted) instead of retraining
    automatically.
  - If automatic resume is wanted, `next_lba` has to be kept outside the reset domain.

### M4. DRAIN can hang forever, so Flush and shutdown never happen

- **Where:** `nvme_host_core.sv:337` `assign all_slots_free = slots_idle && (slot_full == '0);`;
  `nvme_write_engine.sv:181-182`:
  ```systemverilog
  assign want_data = enable && !flush_req && !lba_range_err && slot_full[next_slot] && !busy[next_slot] && ...
  ```
  together with `:331-332` (`lba_range_err <= 1'b1;` is sticky) and `host_sequencer.sv:158-165`.
- **Problem 1: namespace too small.** When NSZE is smaller than the stream, `lba_range_err` stops submission. The full
  ring slots are then never submitted or freed, `slot_full != 0` for good, and DRAIN never ends.
- **Problem 2: no I/O timeout.** A command whose CQE never arrives (firmware hang, dropped MWr) keeps
  `outstanding != 0` forever. `tick_ms` is an unused port: `nvme_write_engine.sv:69`, and the synthesis log reports
  Synth 8-7129 "Port tick_ms … has no load".
- **Why it matters:** in both cases the sequencer never reaches FLUSH or SHUTDOWN. A consumer SSD (no power-loss
  protection) is then powered off with its volatile write cache dirty and without CC.SHN. That is exactly the case that
  ARCHITECTURE D14 is meant to prevent.
- **Fix:**
  - In DRAIN, accept "nothing outstanding" as done when `lba_range_err` is set:
    `all_slots_free = slots_idle && ((slot_full == '0) || lba_range_err);`
  - Add a per-command age check using `tick_ms` (for example, more than 2 s gives a sticky `io_timeout` and the
    sequencer goes to FLUSH/SHUTDOWN anyway). Expose both flags in the status outputs.

### M5. The data-input FIFO reports `s_data_tready=1` and drops the beats while `data_rst` is asserted (from power-up until the first PHY link-up)

- **Where:** `rtl/common/axis_fifo_async.sv:56-57, 61-67, 77-79`:
  ```systemverilog
  assign s_tready  = ~full_q;          // full_q is reset to 0 -> ready=1 during reset
  assign push      = s_tvalid && ~full_q;
  if (s_rst) begin wr_bin_q <= '0; ... end          // pointer does not advance -> beat lost
  ```
  `nvme_host_top.sv:165` `assign data_rst_async = ~board_rst_n | user_reset;`. The IP holds `user_reset_out` high until
  `pl_phy_lnk_up` (`pcie_7x_0_core_top.v:1101`), which is hundreds of milliseconds after power-up and again on every
  link retrain (see M3).
- **Problem:** AXI-Stream handshakes complete (`tvalid && tready`) but the data is discarded. The producer has no other
  signal that tells it when the recorder can actually accept data.
- **Why it matters:** a source that starts streaming at power-up, or keeps streaming across a link retrain, loses data
  with no indication. The `beats_in` counter does not see these beats either.
- **Fix:** hold `s_tready` low while the write side is in reset, using a registered flag so that no combinational
  reset reaches the output:
  ```systemverilog
  always_ff @(posedge s_clk) s_in_rst_q <= s_rst;
  assign s_tready = ~full_q & ~s_in_rst_q;   assign push = s_tvalid & s_tready;
  ```
  Also export a `data_ready` status. ARCHITECTURE §5.9 should state that `s_data_tready` is the only valid handshake.

### M6. MDTS is never checked, and failed I/O commands drop their data with no indication other than a counter

- **Where:** `nvme_admin.sv:636` (`mdts <= ident_rd_data[8*IDC_OFS_MDTS +: 8];`). The value is only exported as
  `stat_mdts` (`nvme_host_core.sv:429`) and `nvme_host_top.sv:201` leaves that port unconnected.
  `nvme_write_engine.sv:376-382` frees the slot whatever the status was:
  ```systemverilog
  if (cqe_status != 15'd0) cmd_errors <= cmd_errors + 1'b1;
  ... busy[cqe_slot] <= 1'b0; wait_clear[cqe_slot] <= 1'b1; slot_free[cqe_slot] <= 1'b1;
  ```
- **Problem:**
  - With MDTS != 0 and `2^MDTS × 4 KiB < SLOT_BYTES` (for example MDTS=4 with the default 128 KiB slots, or any
    `SLOT_BYTES` override above the drive's limit), every Write completes with Invalid Field (SCT0/SC 02h). The engine
    still frees the slot and advances `next_lba`, so the run "succeeds" with `bytes_done=0`.
  - A larger constraint is not asserted either: `SLOT_BYTES > 2 MiB` needs a chained PRP list, which `prp_synth` cannot
    produce (`prp_synth.sv:227` serves one 4 KiB list page per slot). `data_ring.sv:70` only checks for a power of two
    of at least 4096.
- **Why it matters:** the recording is lost without an error code. The ARCHITECTURE requirement (§6:
  "must be ≤ 2^MDTS pages") is not enforced.
- **Fix:**
  - In `S_EX_CHK` step 0: `if (mdts != 0 && (SLOT_BYTES >> 12) > (1 << mdts)) do_fail(F_MDTS);` (CAP.MPSMIN=0 is already
    enforced).
  - Add an elaboration check `SLOT_BYTES <= 2*1024*1024` next to the existing `$fatal` in `data_ring.sv`.
  - Make the first I/O error sticky (`io_error`, `last_status`) on a status pin. Optionally stop submitting and go to
    DRAIN, which is the behaviour a recorder normally wants.

## 3. MINOR

### m1. The requester uses 8-bit tags even when the Root Port's Extended Tag Enable is 0
`rp_requester.sv:245-248` (`tag_q <= tag_q + 8'd1;` wraps through 0..255). `rp_cfg_init.sv:72-74` writes RP DevCtl[8] =
`ext_tag_en`, which is 0 when the SSD has no ETFS (`pcie_enum.sv:334`). PCIe requires the upper three tag bits to be 0
when ETE=0. Enumeration plus init and CSTS polling issue more than 32 non-posted requests, so tags of 32 and above are
used. Most completers simply echo the tag, but this is still a spec violation that the model cannot detect.
**Fix:** `tag_q <= {3'b000, tag_q[4:0] + 5'd1};`. Only one request is ever outstanding, so 5 bits are enough.

### m2. CSTS.RDY=0 is not awaited when CC.EN already reads 0
`nvme_admin.sv:489-494`: `if (mm_rdata[0]) ... disable ... else state <= S_CLEAR_PULSE;`. NVMe requires CSTS.RDY=0
before EN is set to 1. A controller that is still finishing a previous reset or shutdown (EN=0, RDY=1) receives EN=1 while
RDY=1, which the spec leaves undefined. Linux always waits for RDY=0.
**Fix:** always enter `POLL_RDY0` (start at `S_CC_DIS_DONE`), even when EN=0.

### m3. SQES/CQES are checked for exact equality
`nvme_admin.sv:642`: `if (ident_rd_data[7:0] != SQES_EXPECT || ident_rd_data[15:8] != CQES_EXPECT)`. The spec defines
[3:0] as the required size and [7:4] as the maximum. A controller that reports, for example, SQES=0x76 is valid but is
rejected here.
**Fix:** check `SQES[3:0] <= 6 && SQES[7:4] >= 6`, and the same for CQES with 4.

### m4. Double store-and-forward on TX: `tx_str=0` plus the fabric S&F FIFO
`pcie7x_tx_adapt.sv:63` (`assign s_axis_tx_tuser = 4'b0000;`) and `:198-211` (packet-count release). The fabric FIFO
already guarantees that `tvalid` never drops inside a packet, but with `tx_str=0` the core buffers each TLP again before
sending it. This adds about 17 cycles per 256 B CplD on top of the 17-cycle fabric S&F, so first-byte latency goes from
about 8 to about 40 cycles. ARCHITECTURE §8 targets 12 cycles or fewer.
Throughput is unaffected. The extra latency reduces the SSD's read window efficiency only slightly; the Little's-law
budget in research/02 §7 still holds.
**Fix:** set `s_axis_tx_tuser = 4'b0100` (`tx_str=1`) while `STORE_AND_FORWARD=1`. The Xilinx Root Port examples do this:
`rp_cgator_pkt_generator_vlog.ttcl:155`, `rp_pio_master_pkt_generator_vlog.ttcl:193` (`4'b0100; // Enable streaming`).
Also update the §8 latency figure.

### m5. The `rx_np_ok` threshold ignores MRds already queued inside `pcie7x_rx_adapt`
`hostmem_completer.sv:208` (`assign np_backpressure = reqf_afull;`, count of 14 or more out of 16) and
`pcie7x_rx_adapt.sv:83`. Up to `HDR_FIFO_DEPTH=8` MRd headers can wait in the adapter's shared header FIFO, behind which
CQE MWr and requester CplD are blocked (head-of-line). The design is lossless and meets PG054 ("≥2 clocks before the
second-to-last NP"), but `rx_np_ok` was meant to let posted and completion TLPs bypass NP TLPs in the core, and that
benefit is partly lost.
**Fix:** count MRds end to end: +1 when the adapter pushes an MRd header, −1 when the completer pops `reqf`. Deassert
`rx_np_ok` when that count reaches the reqf depth minus 2.

### m6. No link-up timeout, and nothing is visible while the core is held in reset
`link_bringup.sv:293` (`S_WAIT_LNK: if (lnk_up_s) ...`, no timeout) and `host_sequencer.sv:129` (`ST_LINK` waits with no
limit). If training never succeeds (lanes, refclk, PERST# polarity), PERST# stays released forever. Because the IP holds
`user_reset_out` until the first PHY link-up, every `status_*` output stays at its reset value, so the failure cannot be
told apart from "not started".
**Fix:** add a WAIT_LNK timeout (for example 1 s) that returns to HOLD and counts retries. Export `perst_n`,
`pl_ltssm_state` and a retry count from the `link_clk` domain, which is not reset by `user_reset`.

### m7. Safety-relevant status is computed but not exported
- `nvme_host_top.sv:198`: `.status_shutdown_timeout()` is left open, so the user cannot tell whether the SSD actually
  reached SHST=10b.
- `doorbell_err` (`nvme_host_core.sv:387, 404`), `demux_drop_inc`/`writer_drop_inc` (`:141`) and `stat_unexpected_cpl`
  (top) are also unused or unconnected. These are the first things to check during bring-up (for example, CQE MWr
  dropped by a decode bug).

**Fix:** bring them out, or at least latch them into a status word for the ILA/VIO top (B1).

### m8. CDC constraints and attributes
- `kc705_fmc_m2_cdc.xdc:10-13`: `set_clock_groups -asynchronous` (added during the review, implementation only) plus
  the blanket `kc705_fmc_m2.xdc:30` `set_false_path -to [get_cells -hier -filter {ASYNC_REG == TRUE}]` remove every
  constraint on the gray-coded pointer
  buses of `axis_fifo_async` (`:50, :83`). Bit-to-bit skew is then unbounded. If skew exceeds one source clock period, a
  sample can show an invalid code. Use `set_max_delay -datapath_only <min period>` (or `set_bus_skew`) from
  `wr_gray_q`/`rd_gray_q` to the first synchroniser stage, instead of the false path.
- The blanket false path also matches IP-internal `ASYNC_REG` cells (for example
  `(* KEEP, ASYNC_REG *) user_lnk_up_int` in the core). Scope it to `u_core`/top-level cells.
- `link_bringup.sv:241-248`: the 2-FF synchronisers (`lnk_up_s1`, `ltssm_s1`, ...) have no `(* ASYNC_REG = "TRUE" *)`,
  although the XDC comment (`kc705_fmc_m2.xdc:26-27`) says they do. The same applies to `data_ring.sv:163` (`stall_s1`). Without the
  attribute there is no MTBF-aware placement. Before the clock groups were added, this produced
  `synth_methodology.rpt` TIMING-6/7 critical warnings (refclk_odiv2 ↔ userclk2 timed as related).
- `nvme_host_top.sv:165`: a LUT drives an asynchronous reset (`~board_rst_n | user_reset`), reported as LUTAR-1. This is
  acceptable (the inputs are quasi-static), but add a comment or waiver.

### m9. Data-ring read fan-out: one address register drives 256 RAMB36
`data_ring.sv:137-147`: 8 slots of 8 K×128 give 32 RAMB36 per slot (`runme.log` BRAM table), about 60 % of the device's
BRAM. `d.rd_addr`/`rd_en` from the completer drive all of them, and the 8:1 read mux plus the 4:1 `hostmem_rams` mux feed
a LUTRAM FIFO write. These paths are not in the post-synthesis top 10, but after placement they span the whole BRAM area.
**Fix:** if `impl_1` shows these paths, add one address pipeline stage (and one more cycle of read latency in the
completer's tag pipeline; `RET_DEPTH` credits absorb it), or set `max_fanout` on `d.rd_addr`.

### m10. The ODIV2 clock frequency is still 100 MHz in the documentation and in the `link_bringup` default
Vivado derives `refclk_odiv2` with a 20 ns period, which is 50 MHz (`synth_timing_summary.rpt` intra-clock table:
WPWS 9.650). The IBUFDS_GTE2 unisim model also divides by 2. The top now passes `LINK_CLK_HZ = 50_000_000` (fixed
during the review), but `link_bringup.sv:183` (`CLK_HZ = 100_000_000`) and ARCHITECTURE.md §5.12 (line 327) and §4
(line 150) still say 100 MHz. With the old value every PERST#/100 ms timer ran twice as long. That is safe, but the
documentation teaches the wrong number.

### m11. The completer derives LA and the MPS boundary from the region-relative address
`hostmem_completer.sv:282` (`off_dw = {1'b0, w.rel[11:2]} & (mps_dw - 1)`) and `:289`
(`a_la = w.first ? w.la_first : {w.rel[6:2], 2'b00}`). Both are correct only because every region base in
`nvme_host_pkg.sv:23-29` is 4 KiB aligned. Moving a base, for example to an unaligned DDR window, would silently break
LA/RCB conformance.
**Fix:** add an elaboration assertion that every `*_BASE[11:0] == 0`, or carry the absolute address.

### m12. Failure paths leave the SSD enabled
In `host_sequencer` ERROR (admin failure after CC.EN=1, link lost, enumeration failure after BME) nothing attempts
`CC.EN=0` or `CC.SHN`. That is acceptable for a first bring-up, but document it. Ideally run `nvme_admin` shutdown
whenever `init_done` or `CC.EN` has been set.

## 4. NIT

- **n1.** `pcie7x_wrapper.sv:10-11` says the wrapper "is NOT part of rtl/filelist.f", but `rtl/filelist.f` lists
  `rtl/pcie/pcie7x_wrapper.sv`. Only the simulation lists exclude it.
- **n2.** `nvme_admin.sv:447-453`: the "response in the same cycle (fast requester)" branch is dead code, because
  `rp_requester` drives `rsp_valid` only in `S_RSP`, after `req_ready` (`S_IDLE`) has been consumed.
- **n3.** `nvme_write_engine.sv:69` `tick_ms // unused` produces a synthesis warning. Use it for M4 or remove it.
- **n4.** ARCHITECTURE §6 says `SLOT_BYTES` is a "multiple of 4096", but RTL requires a power of two

## 5. Checked and found correct

**TLP formats (`nvme_host_pkg.sv`)**
- `hdr_mrd32` / `hdr_mwr32` / `hdr_cfg0` / `hdr_cpl` field placement: Fmt/Type, TC[22:20], TD, EP, Attr[13:12], Length[9:0].
- DW1: ReqID / Tag / LBE / FBE. Completion DW1: CplID / Status / BCM / BC. Completion DW2: ReqID / Tag / LA.
- CfgRd0/CfgWr0: Length=1, TC/Attr=0, LBE=0, H2 = `{bdf, 4'b0, extreg, reg, 2'b00}`.
- `bc_from_fbe` matches PCIe Table 2-27 for all 16 FBE values. Zero-length read gives BC=1.

**Byte order**
- Confirmed against Xilinx's own templates:
  - `PIO_EP_MEM_ACCESS_vlog.ttcl:112` `w_wr_data_b0 = wr_data[31:24]`;
  - the cgator ROM writes Command=0x0006 as `h06000000` (`rp_cgator_cfg_rom_data_vlog.ttcl:131`).
- Both adapters swap payload DWs only, in both directions (`pcie7x_rx_adapt.sv:288`, `pcie7x_tx_adapt.sv:93/136/141`).
  Header DWs and `cfg_mgmt_*` are not swapped.
- So config values, NVMe registers, SQEs, CQEs, Identify data and ring data are all little-endian / memory order
  internally. `s_data_tdata[7:0]` lands at LBA byte 0.

**RX adapter**
- Bit positions: is_sof = `tuser[14:10]` (SOF at DW2 when `[13]`), is_eof = `tuser[21:17]` (EOF DW = `[20:19]`).
- All four SOF/header cases: 3DW@0 → lane 3; 4DW@0 → next beat lane 0; 3DW@2 → next beat lane 1; 4DW@2 → next beat lane 2.
- Straddle (EOF of A in DW0/1 plus SOF of B at DW2, including A being in `hdr_wait`).
- Payload count taken from Length, which also strips the TD digest.
- `err_fwd` latched per packet, applied to the starting packet on a straddled beat. `ecrc_err` taken at EOF.

**TX adapter**
- 3DW left shift gives `{D0,H2,H1,H0}`. Header-only 3DW goes out as one beat with `tkeep=0x0FFF`. 4DW passes through.
- Last-beat `tkeep` is in {000F, 00FF, 0FFF, FFFF} and contiguous. `tlast` correct. No `tvalid` gaps inside a TLP.
- FIFO depth 64 is at least 2 × 17 beats, so 256 B CplDs stream back to back.

**Completer (`hostmem_completer`)**
- Splits at MPS-aligned boundaries, which is RCB-legal for both 64 B and 128 B RCB.
- BC uses `len*4 − lead − trail` for the first CplD and decrements correctly; 4096 encodes as 0.
- LA: first CplD uses the first enabled byte, later ones the 7 LSBs of their start address.
- Length=1024 encodes as 0. TC/Attr copied. UR as a header-only Cpl. 4DW with a non-zero upper address gives UR.
- Requests are served in FIFO order, so CplDs come out in increasing address order.
- The descriptor/issue pipeline has no bubble between CplDs or between requests. The credit counter makes return-FIFO
  overflow impossible. `prp_synth` entries are `DATA_BASE + k·SLOT_BYTES + (i+1)·4096`, and entries past the slot read as 0.

**`cfg_mgmt` (`rp_cfg_init`)**
- dwaddr 0x001 = 0x0000_0006 with BE 0001; 0x006 = 0x0001_0100 with BE 0111.
- 0x01A read-modify-write of [7:5] MPS and [8] ETE with BE 0011.
- Enables held until `rd_wr_done`, with an idle gap after each access. Values are not byte-swapped.

**Enumeration (`pcie_enum`)**
- BAR0/BAR1 sizing and assignment.
- Capability walk with DW-aligned, range-checked pointers and a hop limit.
- DevCap MPSS/ETFS give `min(MPSS, MPS_CAP_CODE)`.
- DevCtl: MPS/MRRS/ETE inserted and other bits preserved, BE 0011.
- Command 0x0406 with BE 0011, written after DevCtl.
- CRS retried with a 1 ms delay, up to 1000 times per request. UR, CA and timeout fail.

**NVMe (`nvme_admin`, `nvme_write_engine`)**
- CAP fields: MQES, TO, DSTRD, CSS[37], MPSMIN; MQES ≥ 63 checked.
- CC = 0x00460000 then 0x00460001. AQA = 0x001F001F. ASQ and ACQ written low half then high half.
- `doorbell_addr()` = `BAR0 + 0x1000 + (2q + is_cq)·(4 << DSTRD)`, so DSTRD ≠ 0 works.
- Admin SQE layout and values for Identify (CNS 1 and 0), Set Features FID 7, Create CQ (0x003F0001 / 1),
  Create SQ (0x003F0001 / 0x00010001), Delete SQ and Delete CQ.
- Write SQE: CID = slot, PRP1 = slot base, PRP2 = list pointer (or the 2nd page when the slot has 2 pages, 0 when it has
  1), SLBA in DW10/11, NLB = (SLOT_BYTES >> LBADS) − 1. That gives 255 at LBADS=9 and 31 at LBADS=12, and `next_lba`
  steps accordingly. DSM 0x40.
- Identify offsets: MDTS 77, SQES/CQES 512/513, VWC 525, NSZE 0-7, FLBAS 26, LBAF at 128 + 4n with LBADS [23:16] and MS [15:0].
- CQE handling: P = DW3[16], status = DW3[31:17], CID = DW3[15:0]. Phase starts at 1 and flips at wrap
  (31 for the admin CQ, 63 for the I/O CQ). Head and tail stay within [0, size − 1].
- The I/O CQ reaper handles the 2-cycle RAM latency (`skip_r`).
- CIDs are unique: a slot is gated by `busy`/`wait_clear` until its CQE arrives, and the Flush CID 0xFF never collides.
  The SQ cannot overfill and the CQ cannot fill (at most N_SLOTS+1 outstanding against 64 entries).
- Shutdown: Delete SQ → Delete CQ → CC = 0x00464001 → poll `(CSTS & 0xC) == 0x8`.

**IP configuration and wrapper**
- Every `CONFIG.*` name and value in `create_project.tcl` exists in `pcie_7x_v3_3/component.xml` with the given value
  spelling. Examples: `Trgt_Link_Speed 4'h2`, `Max_Payload_Size 256_bytes`, `Ref_Clk_Freq 100_MHz`, `RCB 64_byte`,
  `Legacy_Interrupt NONE`.
- The IP was generated with no `ip_stage` read-back errors (`fpga/build/create.log`).
- The generated core has NPH=12, RCB=0 (64 B), target speed 2, ExtTag supported and default-enabled, and class code 060400.
- `pcie7x_wrapper.sv` connects exactly the 168 ports of the generated `pcie_7x_0_stub.v` (diffed; none missing, none extra).
- Tie-offs match the Xilinx Root Port `cgator_wrapper`: `tx_cfg_gnt=1`, `rx_np_req=1`, all `cfg_err_*=0`,
  `pl_directed_*=0`, `pl_upstream_prefer_deemph=1`, `pl_downstream_deemph_source=0`, `cfg_ds_*=0` (consistent with
  `RP_ID=0`), `cfg_pm_send_pme_to=0`, `int_pclk_sel_slave=0`.
- `pipe_mmcm_rst_n` is correctly absent: it exists only when `PCIE_EXT_CLK=TRUE`, and `en_ext_clk=false` here.

**Synthesis**
- No latches. No combinational loops reported.
- Every `sdp_ram` is inferred as RAMB36 with a READ_FIRST write port, so a CQ poll that collides with an SSD write returns
  the old data safely.
- The async FIFO is in BRAM. Small FIFOs are in LUTRAM. 270 RAMB36 in total.
- The `$fatal` inside the generate-if in `data_ring` is accepted by Vivado 2022.2.
- The `axis_fifo_async` gray/full/empty logic is correct (registered gray sources, 2-FF synchronisers, full computed from
  the next write pointer).
- `axis_skid`, `axis_fifo_sync`, `tlp_tx_arb` (packet lock, one-requester-after-a-CplD fairness) and `req_mux` are correct.

**Flow control**
- `rx_np_ok` deasserts with 2 free request-FIFO entries plus an 8-deep header FIFO in front. That meets the PG054
  "≥2 clocks before the second-to-last NP" rule, and the path is lossless (see m5 for the head-of-line note).

**Reset and CDC basics**
- `user_reset_out` is used as a synchronous reset. It is deasserted synchronously by the IP.
- `data_rst` is asserted whenever `user_reset` is, so both sides of the async FIFO reset together, apart from the M5
  `tready` issue.
- `ctrl_start`/`ctrl_stop`, `link_ready`, `link_gen2` and `link_width` are 2-FF synchronised with `ASYNC_REG`.
